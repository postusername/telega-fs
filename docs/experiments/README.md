# Эксперименты

Часть параметров telega-fs нельзя выбрать, не померив: размер чанка, лимиты отправки, окно readahead, пороги для мелких файлов и другие. Поэтому перед тем как зафиксировать значения, мы мерили их на настоящем железе и на настоящем Telegram. Отчёты лежат здесь, сырые данные каждого замера лежат рядом в CSV (каталог с тем же номером и именем, что у отчёта).

Инструменты для замеров живут в `tools/bench` и собираются с `-DTELEGA_FS_BUILD_TOOLS=ON`. Сетевые прогоны шли на боевых серверах Telegram: нагрузку несёт бот, аккаунт пользователя только настраивает канал (создаёт его, добавляет бота, удаляет по окончании) и отправляет не больше 50 сообщений за все эксперименты. Тестовый DC Telegram недоступен, поэтому другого пути не было. Каждый отчёт описывает окружение, метод, повторы и то, что не удалось проверить; команды для повтора есть в конце отчётов.

| Отчёт | Что проверяли | Что решили |
|---|---|---|
| [01. E1, размеры патчей](01-e1-patch-sizes.md) | Размеры дельт индекса, время блокировки при заборе патча, стоимость монтирования цепочки | `max_chain` = 16, `checkpoint_ratio` = 0,25, нижнего порога размера снимка нет. Запись патча вынесена из-под блокировки, добавлен промежуточный забор по 2000 строк |
| [02. E2, закрепление в режиме бота](02-e2-bot-pinning.md) | Можно ли хранить голову ФС как закреплённое сообщение и какие права нужны боту | Голова — закреплённое сообщение (20 из 20 циклов). Минимум прав: публиковать и редактировать, рекомендуется ещё удалять. Pin и unpin считаются в лимит наравне с отправкой |
| [03. E3, перебор истории](03-e3-history-scan.md) | Видит ли бот по `getMessages` все сообщения канала, в том числе старые | Видит 100 %, удалённые приходят как `null`. Пачки по 100 с паузой не меньше 10 с (`read_pause` = 10 с): около 17 минут на 10 000 id |
| [04. E4, скачивание диапазонов](04-e4-range-download.md) | Качает ли TDLib только нужный диапазон файла, как получать `file_id` | Диапазоны работают, файл целиком не качается (64 КиБ стоят 256 КиБ трафика и около 0,1 с). После перезапуска `file_id` берётся через `getMessages`; `remote_file_id` жив и через 24 часа |
| [05. E5, лимиты отправки](05-e5-send-limits.md) | Сколько действий и байт в минуту выдерживает бот, сколько нужно параллельных загрузок | `send_rate` = 12 в минуту (граница около 18–20), `send_bytes_rate` = 224 МиБ в минуту, `upload_concurrency` = 2 |
| [06. E6, альбомы](06-e6-albums.md) | Выгодно ли отправлять документы альбомами по 10 | Да для документов до 8 МиБ (в 4,4 раза больше документов в минуту для 1 МиБ), для 16 МиБ выигрыша нет. Альбом стоит 2 действия |
| [07. E7, размер чанка](07-e7-chunk-size.md) | Как размер чанка влияет на скорость заливки, перезапись и скачивание | `chunk_size` = 8 МиБ (3,69 МиБ/с на наборе 2 ГиБ против 2,37–2,50 у 16–64 МиБ) |
| [08. E8, инлайн](08-e8-inline.md) | Сколько данных хранить прямо в индексе (расчёт без сети) | `inline_max` = 4 КиБ, `inline_budget` = 16 МиБ. Критерий ничего не отсёк, экономия сообщений в пределах шума, но читать без сети удобно |
| [09. E9, пакеты мелких файлов](09-e9-packs.md) | Сколько сообщений экономят пакеты, сколько стоит чтение файла из пакета | `pack_threshold` = 4 МиБ, `pack_max_age` = 30 с, `pack_target` = 8 МиБ (E9 выбрал 16, но E7 уменьшил чанк до 8). На наборе «домашний каталог» 9 346 документов вместо 724 926 |
| [10. Первый E2E](10-e2e-basic.md) | Первый запуск настоящей ФС на Telegram: запись, перемонтирование на другой «машине», чтение | Сценарий прошёл. Нашлись кэш TDLib при чтении головы (повтор в окне 90 с) и нехватка одновременных загрузок для альбомов. Чтение без readahead: 1,1 МиБ/с |
| [11. E10, чтение и readahead](11-e10-read-readahead.md) | Как TDLib исполняет скачивания, какое окно readahead нужно | `readahead` = 4 МиБ, `readahead_max` = 32 МиБ: 16,8 МиБ/с против 0,96 без readahead. Приоритеты и продление окна работают как предполагалось |
| [12. E11, снимок без блокировки](12-e11-snapshot.md) | Как снимать копию индекса, не останавливая запись | Срез читательской транзакцией под блокировкой, копия через backup API после неё. Блокировка около 2 мс вместо 4,2 с на миллионе инодов. Блокировка MetaStore должна быть честной (FIFO) |
| [13. Расширенный E2E](13-e2e-resources.md) | Большой файл (10 и 6 ГиБ), видео с перемоткой, холодное чтение при лимите кэша | 14 проверок из 14. RSS демона 68–75 МиБ при копировании, из видео 292,6 МиБ скачано 132,5 МиБ при трёх перемотках, `tdfiles/` не вышел за `cache_limit` |

Значения в таблице выбраны в режиме бота. Для режима пользователя они остаются предварительными: на отдельном аккаунте их не мерили.
