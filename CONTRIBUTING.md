# Как помочь проекту

Спасибо, что заглянули. Ниже всё, что нужно, чтобы PR приняли без лишних кругов. Если вы работаете с агентом (Claude Code, Codex и т. п.), он прочитает `AGENTS.md`: там те же правила и подробный список ловушек.

## С чего начать

- Задачи для первого раза помечены меткой [`good first issue`](../../issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22).
- Мелкий баг или опечатку можно сразу присылать PR'ом.
- Новую функцию или изменение поведения начинайте с issue: опишите, что меняется для пользователя и как это ляжет в спеку (мини-спека на пару абзацев). Так проще договориться до того, как написан код.

## Сборка

Подробности, включая сборку TDLib, — в [docs/build.md](docs/build.md). Самый быстрый старт обходится без TDLib:

```sh
cmake --preset core && cmake --build --preset core && ctest --preset core -LE long
```

Пресет `core` собирает ядро, юнит-тесты и FUSE-тесты на локальном хранилище. Этого хватает почти для любой работы, кроме кода, который говорит с Telegram. Полная сборка (`dev`, `ci`, `asan`, `tsan`, `release`) требует TDLib.

## Как устроен проект

- **`docs/SPEC.md` — источник правды.** Код, который с ней расходится, считается багом. Меняете поведение — правьте спеку в том же PR, и правку спеки ревьюер читает первой.
- Спека описывает систему такой, какая она есть сейчас. Это не журнал изменений и не план. В неё не пишут «добавлено в такой-то версии», «потом сделаем», списки того, чего нет, и ссылки на issues. Новое решение встраивается в текст нужного раздела, как будто так было всегда.
- Вне спеки на её разделы не ссылаются по номеру: номера меняются. В комментарии изложите правило словами.
- Документация и комментарии к устройству пишутся по-русски. Идентификаторы, сообщения коммитов и логи — по-английски.

## Тесты

- Тесты по умолчанию работают на `LocalDirStore`: хранилище в каталоге на диске вместо Telegram.
- Сбои можно вызвать через переменную `TELEGA_FS_FAULTS`: задержки, ошибки, падение на заданном шаге коммита или заливки. Формат описан в `src/store/local_dir_store.h`.
- Код, который работает с TDLib, тестируется на фейковом транспорте (`tests/unit/td/fake_transport.h`, `tests/unit/store/fake_telegram.h`).
- FUSE-тесты монтируют настоящий бинарник во временный каталог. fsx (`tests/integration/fsx`) сверяет ФС с моделью на случайной последовательности операций. Длинные прогоны помечены `long`.
- Исправление бага приходит с регрессионным тестом, который без исправления падает.
- Тесты на параллельность синхронизируются барьерами, а не `sleep` и таймингами.

## Перед тем как открыть PR

- [ ] `tools/ci/check-format.sh` чистый (clang-format 18). Новые файлы сначала добавьте в git, иначе скрипт их не видит.
- [ ] clang-tidy 18 чистый на изменённых файлах, включая тесты: `tools/ci/run-clang-tidy.sh build/ci <файлы>`.
- [ ] Сборка с `-Werror` и GCC, и Clang: пресет `ci`, для Clang отдельный каталог `CC=clang CXX=clang++ cmake --preset ci -B build/ci-clang`.
- [ ] `ctest -LE long` зелёный в `ci`, `asan` и `tsan` (санитайзеры собирайте Clang'ом).
- [ ] Для многопоточного кода: тесты прошли и на двух ядрах, `taskset -c 0,1 ctest ...`. Раннеры CI двухъядерные, и гонки в тестах вылезают там, а не на рабочей машине.
- [ ] Если менялось поведение, спека обновлена. Правка описывает текущее состояние и не превращает спеку в журнал изменений или в план.
- [ ] Если добавлен или изменён параметр конфигурации либо значение по умолчанию, его выбор обоснован экспериментом. Отчёт лежит в `docs/experiments/`: цель, окружение, метод, результаты, вывод, сырые данные в CSV рядом. Каждая точка повторена достаточно раз, чтобы разница не была шумом: локальные замеры не меньше 3 раз, сетевые не меньше 5. Указаны медиана, минимум и максимум, seed случайности фиксирован. Если параметры не менялись, так и напишите в описании PR.
- [ ] Ни секретов, ни сессий в диффе: `api_id`/`api_hash`, токен бота, `cred.secret`, `*.binlog`, каталоги TDLib, keyring, keyfile, логи.

Шаблон PR повторяет этот список.

## Живой Telegram

CI в Telegram не ходит, живые прогоны делаются вручную и только со своими данными:

- **Свой `api_id`** с <https://my.telegram.org>. Чужой `api_id` или `api_id` из чужого проекта использовать нельзя: этого требуют правила Telegram API.
- **Свой бот** от @BotFather и **свой приватный канал**, где бот — администратор с правами публиковать, редактировать и удалять сообщения.
- Нагрузку несёт бот. Аккаунт человека, если он нужен (создать канал), — только для настройки, никаких нагрузочных замеров с него.

E2E-сценарии лежат в `tests/e2e/`. Креды передаются файлом `cred.secret` в корне репозитория (`api-id=…`, `api-hash=…`, `bot-token=…`, файл в `.gitignore`) или переменными `TELEGA_API_ID`, `TELEGA_API_HASH`, `TELEGA_BOT_TOKEN`. Чтобы не создавать канал своим аккаунтом, задайте `E2E_CHAT_ID` с id готового пустого канала. Что проверяет каждый сценарий, сколько он идёт и какие у него переменные, написано в шапке скрипта.

Правила, которые нельзя нарушать ни в коде, ни в прогонах:

- в названии приложения и в `device_model` нет слова «Telegram», `application_version` честная;
- telega-fs действует только по явной команде пользователя и только в своём канале;
- лимиты отправки по умолчанию консервативные. Поднимать их можно только с экспериментом и пониманием того, что за флуд блокируют бота;
- обход ограничений через параллельные соединения запрещён;
- на первом `FLOOD_WAIT` серия замеров останавливается.

## CI и PR из форка

- CI проверяет каждый PR: сборки `dev`, `ci` (GCC и Clang), `core`, `asan`, `tsan`, `release`, тесты без `long`, формат и clang-tidy.
- PR из форка получает только права на чтение и не видит секретов. Они ему и не нужны: CI в Telegram не ходит.
- Собранная TDLib берётся из кэша основной ветки, поэтому PR проверяется за обычное время. В собственном форке первый прогон соберёт TDLib заново, это около 40 минут.
- Первый PR нового участника GitHub запускает только после одобрения мейнтейнера.

## Коммиты и PR

- Сообщения коммитов по-английски, в повелительном наклонении: `Fix pack eviction under staging pressure`.
- Один PR — одна тема. Рефакторинг отдельно от изменения поведения.
- TDLib и зависимости из `cmake/deps.cmake` обновляет мейнтейнер. Если обновление нужно, откройте issue.
- Присылая PR, вы соглашаетесь, что ваш вклад распространяется под лицензией проекта (Apache-2.0).
